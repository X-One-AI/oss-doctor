# Review Runbook

Use this runbook when a new repo-health idea appears.

## Intake Questions

1. Does the idea help someone evaluate an MCP server or agent tool?
2. Is the evidence public and linkable?
3. Can the finding be stated as a fact rather than a score?
4. Does it belong in `mcp-risk-index`?
5. Would publishing it create an unsupported trust or safety claim?

## Outcomes

- `move-to-risk-index`: add as maintenance evidence or limitation.
- `watch`: keep only if evidence may become useful.
- `reject`: delete if it is generic repo health or subjective ranking.
- `reopen`: consider standalone product only if reopen criteria are met.

## Quality Bar

Every kept dimension needs:

- evidence source
- target catalog field
- limitation wording
- no score or trust label
